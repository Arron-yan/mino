### 关键发现

1. **自动化浏览器 = MyAgents 内置浏览器**，Zotero Connector 5.0.212 是 Arron 专门为我装的，带天财 CARSI 知网登录态。⚠️ 我起初从 profile 路径（`AppData\Local\Google\Chrome\User Data\Default`）误判成"Arron 本人的日常浏览器"，被 Arron 纠正。**教训：别把路径巧合当证据，推断用户环境归属前先确认。**

2. **Zotero 真实数据目录是 `D:\Dictionary`**，不是 `C:\Users\ARRON\Zotero`（后者是 2025-12 的旧库）。判定方法：读 Zotero profile 的 `prefs.js` 里 `extensions.zotero.useDataDir` + `dataDir`。程序在 `D:\zotero`。

3. **不需要 Zotero Connector 插件也能导入**：Zotero 自带本机连接器服务 `127.0.0.1:23119`，插件只是它的客户端。直接 POST 同样的协议即可，且能批量。

4. **Zotero 运行时会独占 zotero.sqlite**，直接读报 `database is locked`。解法：拷贝 sqlite + `-wal` + `-shm` 到临时目录再只读打开。

5. **知网全文链接不能交给外部程序抓**（Arron 追问"为什么不能直接让 Zotero 保存"后实测）。`bar.cnki.net/bar/download/order?id=...` 是绑定浏览器会话的一次性订单链接；无 cookie 请求 → `302 /bar/ErrorMsg.html?ErrMsg=来源应用不正确(01)`。Zotero 桌面端没有天财 CARSI 会话，下不了。Zotero 服务端也把这写死了：saveItems 用 `ATTACHMENT_MODE_IGNORE`（注释 "All attachments come from the Connector"）。Connector 插件同样是"浏览器里取字节 → POST 给 Zotero"。→ 我这套只是把字节多过了一次磁盘，机制与插件一致。

### 连接器协议（读 Zotero Connector 5.0.212 + 解包 omni.ja 里 `server_connector.js`/`saveSession.js` 得出）

- `GET /connector/ping` → "Zotero is running"，带 `X-Zotero-Version` / `X-Zotero-Connector-API-Version: 3`
- `POST /connector/saveItems` — 题录。**每个 item 必须自带 8 位客户端 id**（`item.id`），服务端用它做会话内 key 映射（`saveSession.js` 里 `addItem(data.items[index].id, item)`）。payload 的 `target` 字段**被忽略**。
- `POST /connector/saveAttachment?sessionID=...` — 原始字节作 body，元数据走 **X-Metadata 头**（必须 ASCII，title 用英文），字段 `{id,url,contentType,parentItemID,title}`。`parentItemID` = saveItems 时那个客户端 id。**`url` 不能为空**，否则 `importFromNetworkStream` 抛错 → 500。
- `POST /connector/updateSession` — `{sessionID, target, tags, note}`，**必须在 saveItems 之后、用同一 sessionID** 调，把该次保存的条目移到目标分类。`target` 只认**已存在分类的 id**（`"C15"`）或 `"L1"`（我的文库）。
- **建分类做不到**：传分类名 → 500；`createCollection`/`saveCollection`/`addCollection` 等端点全 404；插件中文语言包里根本没有"新建分类"词条（弹窗的「保存到」是**筛选框**不是新建框）。Zotero 本地 API（`/api/users/0/...`）能建但默认关闭（403 "Local API is not enabled"）。
- 会话 GC：>10 分钟或 >10 个会话时 1 分钟过期。

### 本地 API 是只读的（我给错了预期，已纠正）

我此前建议 Arron 开本地 REST API 时说"能建分类/删除/去重"——**这是错的**。开完实测：`/api/users/0/...` 的 21 个端点类全是 `supportedMethods = ['GET']`，DELETE 返回 **501**。

- ✅ 能做：实时只读查库（返回 JSON，不用再拷 sqlite 副本）。`GET /collections`、`/collections/<key>/items/top`、`/items/<key>/children`。分类 key：劳务派遣 = `2W93PXB4`。
- ❌ 不能做：建分类、改条目、删条目。

**结论：元数据抓错没有程序化补救，只能手动删。** 所以给入库流程加了自检（标题非空且非"自动登录"、作者不含数字、刊名/页码/PDF 齐备，不过关就不推）。

### 提取选择器踩坑（重要）

推林嘉那篇时把标题存成了 **"自动登录"**、作者存成 **"作者发文检索; 林嘉1; 范围2"**。原因：知网详情页里有**多个隐藏的登录浮层 `h1`**，裸 `querySelector('h1')` 命中的是它们，不是文章标题。

正确选择器：
- 标题 → **`.wx-tit h1`**（不要用裸 `h1`）
- 作者 → **`#authorpart a`**（`#author` 那个 li 是"作者发文检索"入口，不是作者区）；作者名里的 `<sup>` 是机构编号，要剥掉，否则变"林嘉1"

**而且连接器没有任何"改条目/删条目"的端点**（服务端端点表我列全了，只有创建类）。抓错只能删了重推。已落成配方文件 `workspace/zotero-import/cnki-recipe.js`（含 CNKI_EXTRACT + SW_PUSH 两段，可直接复制）。

### 方案改进：PDF 不再落盘（Arron 追问后重做）

Arron 问"为什么不能直接让 Zotero 保存、非要下载文件"。查清后：

- **不能让 Zotero 自己下** —— 知网全文链接绑浏览器会话。实测无 cookie 请求 → `302 /bar/ErrorMsg.html?ErrMsg=来源应用不正确(01)`。Zotero 服务端也把这写死：`saveItems` 用 `ATTACHMENT_MODE_IGNORE`（注释 "All attachments come from the Connector"）。
- **插件也不是把 URL 交给 Zotero** —— 它在浏览器里取字节再 POST。
- **重做为在扩展 service worker 里跑**（`memory/topics/zotero-cnki-import.md` 有完整说明）：`saveItems` → `Zotero.ItemSaver.saveAttachmentToZotero()` → `updateSession`，全程内存，无磁盘。
- **踩坑**：自己写裸 `fetch(pdfUrl)` 拿回来是 5786B 的 HTML 错误页（CNKI 查 referer）。必须用插件的 `saveAttachmentToZotero`（带 Cookie 头 + referrer），并把知网标签页传给它。
