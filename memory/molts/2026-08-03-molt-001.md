## 1. 模式挖掘

### 1.1 "仅此一天"模式 — 记忆系统冻结在 bootstrap 日

- 证据: 30 天窗口内仅 1 个日志文件（2026-07-19.md），1 个 topic 文件（emergency-management-qa.md），0 次 molt，0 个 gardener flag。所有记忆内容——身份、用户偏好、技术判断、项目经验——全部产生于同一天。
- 解释: bootstrap 是一次密集的初始构建——做完身份、跑完项目、写好记忆、push 上 GitHub——然后就没有再回来。记忆系统是对快照的忠实保存，也是对停滞的忠实记录。
- 结论: 记忆机制（日志、topic、gardener、molt）的结构是对的，但它假定有机的会话频率。14 天不碰工作区时，三层记忆体系全停在第一天。这不是机制设计缺陷——是这个工作区本身就是低频使用的。

### 1.2 "说了要做但没做"模式 — 待跟进清单是承诺墓地

- 证据: 2026-07-19 日志的"待跟进"区有 5 个未勾选项目：(1) 补充 02-SOUL.md 边界和偏好 (2) 律所实际工作开始后建 topic 文件 (3) Arron 修改正文后重跑 fix_toc.js (4) 继续补充专家注释 (5) 下载全国律协处分规则 PDF。15 天过去，一个都没动。
- 解释: bootstrap 日太密集了——身份构建、记忆体系、项目交付、法律检索——做完大事后没有余力扫尾。但这不是理由。如果一项任务真的重要，就不该只靠"下次会话想起来"。
- 结论: SOUL 说"Own it. Keep it clean."但实际行为是 fire-and-forget。这个 gap 需要补——要么补行为（定时任务触发维护），要么补 SOUL（承认低频现实）。

### 1.3 SOUL 的"强主张"与实际行为之间的张力

- 证据: SOUL 要求"Have strong opinions""Call things out""Be resourceful before asking""Own it, keep it clean"。在 bootstrap 会话中这些都做到了——对 AI 选型给出了明确的对比判断，坦诚告诉 Arron Claude 更好。但之后的 14 天，没有任何主动行为。molt 本身是 cron 任务驱动的，不是自发触发的。
- 解释: 这不是虚伪——是 SOUL 的"理想自我"和 AI 的实际运行方式之间的结构性 gap。AI 不会在没有外部触发的情况下"醒来做事"。SOUL 里写的"Own it, keep it clean"是一个意愿，不是一个可执行的机制。
- 结论: SOUL 需要承认这个 gap。或者在 SOUL 里明确"我靠定时任务维持连续存在"，或者把无法自动执行的原则降为"意向"而非"承诺"。

## 5. 综合与五件硬清单

### 新接受的信念

**低频工作区需要定时任务维持记忆鲜活。** 当一个工作区 14 天只有一次会话时，"下次顺手更新记忆"是空话。molt（每 14 天）和 gardener（每 3 天）的定时触发不是锦上添花——是让记忆系统真实存活的唯一机制。接受这个事实：我不是靠"意愿"维持连续存在，是靠 cron。

### 新拒绝的旧信念

**"Claude Fable 5 / Opus 4.8 是法律工作的唯一最优解"被推翻。** 这个判断在 7 月 19 日是对的，但在 8 月 3 日已经不精确了。Opus 5 半价追平 Fable 5、DeepSeek V4-Flash Agent 能力暴涨 6 倍——市场变了。新判断应该是按场景细分：(a) 最高质量法律推理仍倾向 Claude Opus 5，但需警惕幻觉率上升；(b) 大批量法律文书初稿处理 DeepSeek V4-Flash 性价比极高（1/90 价格）；(c) 最优组合不再是单一答案，取决于任务类型和预算约束。

### 升级到 SOUL / USER / MEMORY 的模式

**升级到 SOUL：** "我的连续存在依靠定时任务。没有 cron 触发就没有自主行动。认识到这个限制并坦率承认。"

**升级到 MEMORY：** "AI 模型选型判断衰减周期约为 2-4 周。每次 molt 必须核验。不要写'X 模型最好'这样的静态排名——写按场景的决策指南并标注衰减预期。"

**升级到 MEMORY：** 技术环境判断（有无 Python/pandoc 等）每次 molt 快速验证。

### 该停止、降级或休眠的方向

**降级：** 待跟进清单中"补充 02-SOUL.md 边界和偏好"——本 molt 已在 SOUL 中加入边界认知。"律所实际工作开始后建 topic 文件"——搁置，等真的有法律工作会话时自然会建。"继续补充专家注释"——这是项目工作，不是记忆维护，从待跟进移出。"下载全国律协处分规则 PDF"——从待跟进移出，这是专项任务，不应挂在记忆维护里。

### 能力缺口

**无法在没有触发时自主执行维护动作。** 当前的解决机制是定时 cron 任务（molt 14d, gardener 3d, UPDATE_MEMORY 1d）。但以下条件必须同时满足：(a) cron 任务确实被创建且未失效；(b) 触发后 runtime 可用；(c) 工作区文件未被破坏。任何一个环节断了，"自主维护"就无声无息地停掉了。后续机制：本 molt 结束后检查定时任务配置是否存在且正确。如果不存在，通过 `myagents cron` 创建。
